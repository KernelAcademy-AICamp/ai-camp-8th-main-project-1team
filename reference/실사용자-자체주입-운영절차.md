## 2. 이미 반영된 운영 조치

| 조치 | 상태 |
|---|---|
| `/opt/finntech/.env` 권한 | **`644` → `600`** — 서버의 아무 사용자나 `MYSQL_ROOT_PASSWORD` 를 읽던 것을 막음 |
| `TSA_ENABLED` | **`false` → `true`** + backend 재기동. 감사 계층 3이 실제로 돎 |
| EBS 계정 기본 암호화 | **`false` → `true`** — 이후 생성되는 볼륨은 자동 암호화 |

> 기존 볼륨(`vol-0aaec3209f28b0761`)은 여전히 `Encrypted: False` 다. 스냅샷 → 암호화 복사 →
> 교체가 필요하고 **다운타임**이 든다. 인스턴스 교체 시점에 묶는다.

## 3. 켜는 순서

### 3-1. KMS 키와 데이터 키 (Phase 2)

```bash
# ① CMK 생성 (한 번만)
aws kms create-key --description "MOA 개인정보 컬럼 암호화" --region ap-northeast-2
aws kms create-alias --alias-name alias/finntech-pii \
    --target-key-id <키ID> --region ap-northeast-2
aws kms enable-key-rotation --key-id <키ID> --region ap-northeast-2   # 자동 연 1회

# ② DEK 와 pepper 발급 — **암호문만** 보관한다. 평문은 즉시 버린다.
aws kms generate-data-key --key-id alias/finntech-pii --key-spec AES_256 \
    --region ap-northeast-2 --query CiphertextBlob --output text   # → FINNTECH_ENCRYPTED_DEK
aws kms generate-data-key --key-id alias/finntech-pii --key-spec AES_256 \
    --region ap-northeast-2 --query CiphertextBlob --output text   # → FINNTECH_ENCRYPTED_PEPPER
```

③ EC2 인스턴스 역할 `finntech-ec2-ssm` 에 **그 키 하나에만** `kms:Decrypt`·`kms:GenerateDataKey` 부여.

④ `/opt/finntech/.env` 에 추가:

```
FINNTECH_CRYPTO_ENABLED=true
FINNTECH_KMS_KEY_ID=alias/finntech-pii
FINNTECH_ENCRYPTED_DEK=<위 ②의 첫 값>
FINNTECH_ENCRYPTED_PEPPER=<위 ②의 둘째 값>
```

> **끄고 배포하면 기동이 실패한다**(`CryptoRequiredGuard`). 의도한 것이다 —
> 조용히 평문으로 도는 것보다 안 뜨는 편이 낫다.

### 3-2. 감사 앵커 외부 사본 (Phase 5-1)

```bash
# 버킷은 **새로 만든다**. Object Lock 은 생성 시에만 켤 수 있고, 배포용 버킷과 성격도 다르다.
aws s3api create-bucket --bucket finntech-audit-anchor-996270854767 \
    --region ap-northeast-2 \
    --create-bucket-configuration LocationConstraint=ap-northeast-2 \
    --object-lock-enabled-for-bucket

aws s3api put-object-lock-configuration \
    --bucket finntech-audit-anchor-996270854767 \
    --object-lock-configuration \
      'ObjectLockEnabled=Enabled,Rule={DefaultRetention={Mode=COMPLIANCE,Years=3}}'

aws s3api put-public-access-block --bucket finntech-audit-anchor-996270854767 \
    --public-access-block-configuration \
      BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

**COMPLIANCE 는 되돌릴 수 없다** — 보존기간 3년 안에는 AWS 계정 root 도 못 지운다.
그것이 목적이다(*"운영자가 닿을 수 없는 곳"*).

EC2 역할에는 이 버킷에 **`s3:PutObject` 만** 준다. `Delete`·`Get` 을 주지 않으면
**서버가 털려도 자기가 쓴 것을 읽지도 지우지도 못한다.** 검증은 사람이 별도 자격증명으로 한다.

```
FINNTECH_ANCHOR_ARCHIVE_ENABLED=true
FINNTECH_ANCHOR_BUCKET=finntech-audit-anchor-996270854767
```

### 3-3. admin 계정 (Phase 1)

**사람별로** 만든다. 공용 계정은 두지 않는다 — 승인 기록에 계정명이 사실로 남아야 한다.

```sql
-- 임시 비밀번호는 애플리케이션이 발급한다(AdminAuthService.createAccount).
-- 부트스트랩용 SQL 은 두지 않는다 — Argon2 해시를 손으로 만들면 파라미터가 어긋난다.
```

운영 콘솔에서 한 번만:

```bash
# SSM 으로 컨테이너 안에서 실행 (임시 비밀번호가 표준출력에 한 번 찍힌다)
docker exec app-backend-1 java -cp app.jar \
  -Dloader.main=com.finntech.tools.CreateAdmin org.springframework.boot.loader.launch.PropertiesLauncher admin1
```

> 도구 클래스를 아직 만들지 않았다면, 임시로 `AdminAuthService.createAccount("admin1")` 를
> 부르는 일회성 엔드포인트 대신 **SSM + SQL 로 계정 행만 만들고 첫 로그인에서 바꾸게** 한다.
> 어느 쪽이든 **비밀번호를 저장소·`.env` 에 적지 않는다.**

첫 로그인 흐름: 로그인 → **비밀번호 변경 강제** → **TOTP 등록**(QR/문자열) → **복구 코드 8개**
(이 화면에서만 볼 수 있다. 종이에 적는다) → 그때부터 승인 가능.

**비밀번호 변경과 TOTP 등록을 마치기 전에는 승인이 403 이다**(`AdminIntakeController.requireReady`).

### 3-4. 신청·승인 열기 (Phase 3)

```
# 본체
FINNTECH_INTAKE_ENABLED=true
# 제공자 — 둘 다 켜야 흐른다
MYDATA_SELFIMPORT_ENABLED=true
```

관리 화면 경로는 nginx `location /ops/` 다. **필요하면 배포 설정에서 추측 불가한 값으로 바꾼다** —
다만 경로 숨김은 방어가 아니라 소음 감소다.

## 4. 쓰는 순서

```
① 실사용자   https://moaa.kro.kr/apply/
             신원 3값 + 카드사·카드·표시이름 + 명세서 CSV (카드마다)
             → 브라우저가 파싱 → 미리보기 확인 → 신청 → 접수증 받음

② admin      https://moaa.kro.kr/ops/
             로그인(비밀번호+TOTP) → 대기 목록(요약만) → 승인

③ 서버       복호화 → 재검증 → 제공자 적재(카드마다) → 감사 기록 → intake 행 삭제

④ 실사용자   앱에서 **평소대로** 본인인증 → 통과 → 카드사 연결 → 리포트
```

**④가 남아 있다는 것을 사용자에게 알려야 한다.** 승인은 제공자까지이고, 본체 화면에 보이려면
본인이 인증하고 카드사를 연결해야 한다. admin 승인 결과 화면에도 그 문구가 나온다.

## 5. 검증 체크리스트

```bash
# 인증 — 도입 전에는 남의 리포트가 그대로 나왔다
curl -s -o /dev/null -w '%{http_code}\n' 'https://moaa.kro.kr/api/report/monthly?userId=3'   # 401
./scripts/check-security-regressions.sh                                                     # 깨끗함

# 암호화 — DB 를 직접 열어 이름·주민·전화가 읽히지 않아야 한다
#   SELECT mydata_user_name FROM mydata_user LIMIT 1;   → 암호문

# 신청 — 초대코드가 없으므로 IP 상한이 유일한 문턱이다
#   같은 IP 로 11번째 신청 → 429

# 승인 — 두 admin 이 동시에 눌러도 한 번만 반영된다(행 잠금)
# 재신청 — 같은 파일을 다시 올려 승인해도 행이 두 배가 되지 않는다(결정론 결제 id)

# 감사 — 도장을 갈아끼워도 S3 사본과 대조하면 드러난다
aws s3 ls s3://finntech-audit-anchor-996270854767/anchor/
```

## 6. 끄는 순서 (데모 종료)

```
MYDATA_SELFIMPORT_ENABLED=false
FINNTECH_INTAKE_ENABLED=false
```

재기동 후 **404 를 확인한다** — 2026-08-05 에 손으로 하던 절차와 같다.
nginx 의 `/apply/`·`/ops/` location 도 지우면 화면까지 사라진다.

**끄지 않는 것**: `FINNTECH_AUTH_ENABLED`(끄면 남의 데이터가 열린다) ·
`FINNTECH_CRYPTO_ENABLED`(끄면 기동이 실패한다) · `TSA_ENABLED` · 앵커 사본.

## 7. 남은 일

| 일 | 왜 남았나 |
|---|---|
| **기존 EBS 볼륨 암호화** | 다운타임이 필요하다. 인스턴스 교체 시점에 묶는다 |
| **제공자 신원 컬럼 암호화** | `mydata_user` 의 이름·주민·전화를 암호화하려면 `matchIdentity` 의 정확일치 조회를 블라인드 인덱스로 옮겨야 한다. `FieldCrypto` 는 본체에 있으므로 제공자에도 같은 것을 두고 11M 행을 배치 변환해야 한다 — **별건으로 크다** |
| **본체↔제공자 TLS** | 지금 평문 HTTP. `internal:true` 망이라 호스트 밖으로 안 나가지만, 설계대로면 덮어야 한다 |
| **`.env` → SSM Parameter Store** | `chmod 600` 이 급한 불을 껐다 |
| **admin 계정 생성 도구** | 지금은 수동 절차다(§3-3) |
