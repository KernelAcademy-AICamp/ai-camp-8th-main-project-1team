# 00. 서비스 개요 — MOA

> 이 문서는 처음 합류한 사람이 10분 안에 서비스 전체를 파악하고 필요한 하위 문서로 스스로 찾아 들어가기 위한 **진입점(메인)**이다. 설득이 아니라 안내이며, 결론만 적고 근거는 하위 문서 링크로 넘긴다. 각 파일의 목표·검증 상태와 폴더 정책은 [README](README.md).

---

## 1. 한 줄 정의

**MOA** — 충동 소비 뒤 무엇을 줄여야 할지 몰라 절약을 오래 이어가지 못하는 **20~30대 직장인**이, 이번 달 **지킬 돈**을 스스로 정하고 실제 소비로부터 끝까지 지켜내도록 돕는 소비 관리 서비스.

## 2. 서비스 공식

```text
사용 한도 = 기준 소비 × (1 − 절약 강도)          이번 달 써도 되는 돈 (내부 계산)
지킬 돈   = 기준 소비 × 절약 강도                 이번 달 지키기로 한 돈 (사용자 노출)
지킨 돈   = max(지킬 돈 − max(누적 소비 − 사용 한도, 0), 0)
```

한도를 넘긴 만큼만 지킨 돈이 깎인다. 이것이 유일한 차감 규칙이다. 강도 100%는 사용 한도가 0원이 되어 카테고리 전체 절감과 같아진다 — 전체 절감은 부분 절감의 특수한 경우다.

## 3. 문제와 타깃

**타깃** — 스트레스로 배달·쇼핑·택시를 이용한 뒤 후회하지만, 무엇을 줄여야 할지 몰라 절약을 오래 이어가지 못하는 20~30대 직장인. 절약 의지가 없는 사람이 아니라 가계부·챌린지를 시도했지만 정착하지 못한 사람이다.

**문제** — 충동 소비를 반복하면서도 무엇을 줄여야 할지 판단하지 못하고, 절약의 중간 성과를 월말 이전에 체감하지 못한다. "소비를 더 잘 보여주는" 문제는 일부러 선택하지 않았다.

## 4. 솔루션 컨셉

핵심 전환은 **사후 분석에서 사전 선택으로**다. 기존 앱은 발생한 거래를 보여준 뒤 행동을 사용자에게 맡기지만, MOA는 과거 소비로 이번 달 줄여볼 카테고리를 먼저 고르게 하고 그만큼을 지킬 돈으로 바꾼다. 문제와 해결이 이렇게 맞물린다.

| 문제 (03·01c) | 해결 (05) |
|---|---|
| 무엇을 줄일지 모른다 (P2) | AI가 조정 가능한 카테고리와 근거를 **후보로만** 제안, 사용자가 검수·선택 |
| 절약이 전부 아니면 전무가 된다 | **부분 절감** — 카테고리별 절약 강도로 지킬 돈을 정하고 한도 초과분만 차감 |
| 중간 성과를 월말 전에 못 느낀다 (P1·P5) | Home에 `현재 지키는 금액` 하나, 한도 안에서는 침묵하다 초과 순간부터 실시간 차감 |
| 절약 권유가 잔소리로 느껴진다 (P7) | 선택한 카테고리만 추적, 전체 소비를 평가하지 않음, 비난 없음 |
| 외부 목표가 새 소비를 부른다 | 여행·물건 목표·보상 제거, **캐릭터 여정·성장**(월말 확정 지킨 돈만 누적)으로 동기 치환 |

→ [03_솔루션/02_솔루션컨셉](03_솔루션/02_솔루션컨셉.md)

## 5. 3-Agent 구조

세 팀원이 병렬로 개발하기 위해 역할과 주고받는 데이터를 계약으로 고정했다.

- **① 소비 분석** — 거래 분류·소비 패턴 탐색, 줄여볼 카테고리·기준 소비·추천 근거 제안
- **② 지킴·성장** — 지킬 돈·사용 한도 확정, 누적 소비·초과분 차감·지킨 돈 갱신, 캐릭터 성장 누적
- **③ 취향·추천** — 라이프스타일 분석(자금 흐름 축 + 취향 축), 주간·월간·연간 리포트, 아낀 돈 보관처 금융상품 **정보성 비교**(판매·중개 없음)

```text
① 소비 분석 ──(A) 줄여볼 카테고리·기준소비·근거──▶ ② 지킴·성장
  거래 분류·소비 패턴                              지킬 돈·한도 초과분 차감·캐릭터 성장
     │                                                   │
     │ (B) 소비 요약                         (C) 지킴·성장 상태
     ▼                                                   ▼
              ③ 취향·추천  ◀──(D)── 외부 금융상품 정보
              주간·월말 리포트 · 정보성 비교 추천
                      │
                      ▼
                    사용자
```

금액 계산과 판정은 **규칙 엔진**(주로 ②)이 하고 LLM은 표현만 담당한다. ③은 ①·②의 금액·성장 값을 읽어 서술할 뿐 바꾸지 않는다.

## 6. 핵심 설계 원칙

- **모든 차감은 설명 가능하다.** 깎인 금액과 한도를 넘긴 금액은 언제나 같다. Home에는 지킬 돈 하나만 두고 기준 소비·사용 한도는 내부 계산으로 숨긴다(계산과 노출 분리).
- **성장은 월말 확정 금액만 먹고 뒤로 가지 않는다.** 월중 금액은 환불·재분류로 바뀔 수 있어 성장에 즉시 반영하지 않는다. 0원을 지킨 달에도 감소·비난·퇴화는 없다.
- **하지 않기로 한 것** — 여행·물건 목표·도착률·보상·금융상품 판매 추천을 코어 루프에서 제거했다(절약이 새 소비를 부르는 모순). 참기 세션·자기 보고·지킨 날 원장·보호 쿠폰·위젯도 폐기했다(기록 부담·원장 중복).

## 7. 현재 상태와 다음 단계

세대2(MOA)의 부분 절감 모델·3-Agent 계약·1차 구현 범위까지 기획이 확정됐다. 아직 **검증 전**이며, 북극성 지표·기준값, 절약 강도 단계(20/50/100% 잠정), 기준 소비 산출식, 금융상품 정보 출처는 미확정이다.

다음 단계는 실제 사용자 인터뷰(P3 최우선 검증)와 프로토타입으로 솔루션 가설 S1~S11을 확인하는 것이다. AI 가상 인터뷰 결과는 실제 근거로 쓰지 않는다.
