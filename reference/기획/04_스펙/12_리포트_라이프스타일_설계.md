## 1. 제품 철학

가계부 앱은 보통 사용자를 교정하려고 한다. 우리는 교정하지 않는다.

**서비스의 역할은 판단자가 아니라 거울이다.** 사용자가 데이터를 보고 스스로 의미를 발견하도록 설계한다.

---

## 2. 핵심 원칙

> **AI는 소비를 설명하고, 소비의 의미는 사용자가 결정한다.**

```text
O  "이번 달 택시비 8만 원 중 5만 원이 평일 오전에 발생했어요."
O  "올해 가장 많이 택시를 탄 시간대는 오전 8~9시였어요."

X  "출근 때문에 택시를 많이 타시네요."
X  "지각 방지 택시가 반복되고 있어요."
X  "이 소비는 필수 소비예요."
```

### 2.1 왜 해석하지 않는가

AI의 정확도 문제가 아니다. **사용자가 "평가받고 있다"고 느낄 위험** 때문이다.

같은 데이터가 전혀 다른 사정을 담는다.

```text
데이터    오전 8~9시 택시 12회
해석 시도  "지각 방지 택시가 반복되고 있습니다"
실제 이유  출근 · 등원 · 병원 · 미팅 · 그날만의 사정 …
```

하나를 골라 말하는 순간 나머지 사정을 가진 사용자는 오해받는다. 그래서 **현 단계에서는 의미를 단정하지 않고 사실만 전달한다.**

## 3. 리포트 3종

### 3.1 주간 = 관찰

**이번 주 어떤 소비가 있었는지.**

| | |
|---|---|
| 포함 | 카테고리별 소비 · 시간대 패턴 · 요일 패턴 · 소비 흐름 |
| 포함 | **지키는 금액 — 사실로서만** |
| 금지 | 목표 달성 여부 · 잘했다/못했다 · 페이스 평가 · 행동 교정 |

```text
O  "배달 3건이 화·목·금 밤에 있었어요."
O  "이번 주 카페에서 4번, 21,000원 썼어요. 지금 100,000원 지키는 중이에요."

X  "이번 주 목표의 80%를 달성했어요."
X  "이 페이스면 이번 챌린지는 어려워요."
X  "주말엔 배달을 줄여보세요."
```

> **금액과 평가의 경계.** `100,000원 지키는 중`은 **상태 사실**이라 넣는다. `달성률 80%`·`이 페이스면`은 **평가**라 뺀다. 금액을 숨기면 사용자가 홈에서 본 숫자와 리포트가 어긋나 오히려 혼란스럽다.
> ②의 `achievementRate`·`paceRatio`는 주간 리포트에 쓰지 않는다.

### 3.2 월간 = 회고

**이번 챌린지에 어떤 흐름이 있었는지.** 주기는 달력 월이 아니라 **챌린지 종료일**이다(`11_지킴이_Agent_설계.md` §0.2).

| | |
|---|---|
| 포함 | 지킨 금액 · 소비 카테고리 비중 · 직전 챌린지 대비 변화 · 반복적으로 나타난 패턴 |
| 포함 | **취향 축의 집계 사실** — `이번 챌린지 카페 12번 · 영화 2편` |
| 금지 | 실패 · 합격/불합격 · 절약을 못했다는 평가 |
| 금지 | **취향 해석** — `당신은 미술 애호가` 같은 정체성 서술은 연간에서만 |

```text
O  "이번 챌린지 택시비의 62%가 평일 오전에 발생했어요."
O  "지난 챌린지보다 카페 소비가 3건 줄었어요."

X  "목표 달성에 실패했어요."
X  "절약이 부족했어요."
```

②의 `state`가 `SHORTFALL`·`FAILED`여도 그 이름을 노출하지 않는다. 사실(지킨 금액·흐름)만 말한다.

### 3.3 연간 = 정체성

**올해 나는 어떤 사람이었는지.** Spotify Wrapped와 유사한 경험.

| | |
|---|---|
| 포함 | 연간 소비 사실의 집계 — 횟수·장소 수·시간대 |
| 포함 | **제한적 취향 서술 (§5)** — 세 리포트 중 여기서만 허용 |
| 주기 | **달력 연도.** 챌린지 경계와 맞추지 않는다 |

```text
영화 32편 관람 · 전시 9회 방문 · 새로운 식당 47곳 방문
→ "올해의 영화 러버"
→ "새로운 경험을 즐긴 한 해"
```

연간은 챌린지 실적이 아니라 **소비 사실**을 재료로 하므로 챌린지 주기에 맞출 이유가 없다. 챌린지를 하지 않은 기간의 소비도 포함한다.

### 3.4 주기 정리

| 리포트 | 주기 | 성격 | ②의 금액 |
|---|---|---|---|
| 주간 | 챌린지 시작일 기준 7일 (§8 미정) | 관찰 | `securedSaving`만 |
| 월간 | 챌린지 종료일 (30일) | 회고 | 확정 지킨 돈 |
| 연간 | 달력 연도 | 정체성 | 쓰지 않음 |

## 4. 라이프스타일 분석 — 한 이름, 두 축

③의 분석 축은 **라이프스타일 분석** 하나다. 그 안에 성격이 다른 두 축을 둔다.

```text
마이데이터 · ①의 (B)
  ├─ 금액 · 시점 · 규칙성   →  자금 흐름 축 (L1~L5)  →  저축 상품 매칭 (FP-01)
  └─ 카테고리 · 가맹점 빈도  →  취향 축  ┬──────────▶  월간 리포트 (집계 사실)
                                        ├──────────▶  연간 리포트 (정체성)
                                        └──────────▶  카드 추천 (FP-03)

                              취향 축 ──✕──▶ 저축 상품 매칭
```

### 4.1 자금 흐름 축 (L1~L5)

| 축 | 계산값 | 출처 |
|---|---|---|
| L1 소득 | `salary_regular` · `salary_day` | (B) `income_profile` ← ① |
| L2 고정비 | `fixed_total` · 인출일 분포 | (B) `fixed_expense_summary` ← ① |
| L3 안정성 | `aom`(Age of Money = 자금 버퍼) · 규모는 `kept_mean` | (B) `cash_buffer` ← ① · kept_mean은 (C) ← ② |
| L4 유동성 | `large_expense_cycle` · `predictable` | (B) `recurring_payments` + 큰 1회성 지출 ← ① |
| L5 우대조건 | **카드 실적 · 급여이체** 충족 여부 | (B) `preferential_material` × (D) ← ①·외부 |

**대부분 ①에게서 온다.** ③이 직접 계산하지 않고 (B)로 받는 이유는 R7이다 — 급여·고정비·잔고는 계좌를 봐야 알 수 있는데 ③은 계좌 원본을 만질 수 없다. L3(AoM)도 ①이 (B) `cash_buffer`로 넘긴다. 규모용 `kept_mean`만 ②의 확정 이력에서 온다.

매칭 규칙 M1~M9는 `_수정안_③_라이프스타일전환.md` §5를 정본으로 삼는다. 규칙 엔진이 판정·정렬을 하고 LLM은 문장만 만든다(R2).

**L5는 카드 실적·급여이체 둘만 본다.** 자동이체는 더미에 해당 거래가 없어 제외했다(R7). 실제 적금 우대조건에서 가장 흔하고 가산폭도 큰 두 가지가 남았으므로 D2는 그대로 성립한다.

> ### ✅ L3 재정의 — kept 변동성 → AoM(Age of Money) (2026-07-28 해결)
>
> 옛 L3(`kept_cv` 지킨 돈 변동성)는 저축 여력이 아니라 **사용자의 목표 변경 빈도**를 재는 결함이 있었다 — 지킬 돈은 매 챌린지마다 사용자가 카테고리·강도를 새로 골라 달라지므로, 소비 습관이 그대로여도 `kept_cv`가 크게 나온다. 결과적으로 M2(정액 적금)가 죽은 규칙이 되던 문제.
>
> **해결**: 안정성은 목표 선택과 무관한 **AoM(자금 버퍼)** 으로 잰다 — 간이식 `평균잔고 ÷ 월평균지출`. 실제 입출금 현금흐름으로 계산돼 챌린지 선택에 오염되지 않고, 마이데이터로 **가입 첫날부터** 계산되어 콜드스타트도 완화된다. `kept_mean`은 *납입 규모* 산정에만 쓴다.
>
> 더불어 MOA의 지킨 돈은 매달 금액이 다르고 덩어리로 들어와 **정액적금과 구조적으로 안 맞으므로**(고정 납입 강제 = R9 페이스 유도 위험), 중심축을 "정액 vs 자유"가 아니라 **파킹통장 ↔ 자유적립식**으로 바꾼다(AoM·L4 주도). 상세 규칙은 `_수정안_③_라이프스타일전환.md` §5(M1~M9).
>
> **남은 미정**: θ_buffer(버퍼 구간)·간이 vs 정통 AoM·카드-현금 시점 차이 보정 → §8.

### 4.2 취향 축

카테고리·가맹점 빈도에서 나오는 것.

```text
영화관 결제 32회 · 전시 9회 · 처음 가본 식당 47곳
```

**재료와 해석을 나눈다.** 같은 축이지만 어디까지 말하느냐가 다르다.

| 쓰이는 곳 | 어디까지 |
|---|---|
| 월간 리포트 | **집계 사실까지** — `이번 챌린지 카페 12번` |
| 연간 리포트 | **정체성 서술까지** — `당신은 미술 애호가` (§5) |
| **카드 추천 (§4.4)** | 소비처별 혜택 매칭의 입력 |
| ~~저축 상품 매칭~~ | **금지** (§4.3) |

### 4.3 왜 경로를 나누는가

취향이 **저축** 상품 매칭 입력으로 들어가는 순간 이런 문장이 만들어진다.

```text
X  "영화를 좋아하시니, 영화값 모으는 적금 어떠세요?"
```

**소비 목표를 만들어 유도**하는 것이라 R9 위반이다. 규칙으로 "쓰지 말자"고 막는 대신 **입력에서 빼서 구조적으로 불가능하게** 만든다. 규칙은 잊히지만 없는 데이터는 쓸 수 없다.

두 축은 포함 관계가 아니라 **직교**다. 취향이 같아도 자금 흐름이 다르면 추천이 갈린다.

```text
둘 다 영화 32편을 본 사람 —
  A  급여 25일 규칙적(L1) · 큰 지출 없음(L4)   → 만기 긴 상품도 가능
  B  수입 불규칙(L1) · 분기마다 큰 지출(L4)    → 만기 짧은 상품·파킹통장
```

### 4.4 카드 추천 (FP-03)

취향 축이 상품 매칭에 쓰이는 **유일한 자리**다. 저축(FP-01)과 근거가 반대다.

| | FP-01 저축 | FP-03 카드 |
|---|---|---|
| 매칭 근거 | 자금 흐름 축 + 우대조건 | **취향 축 — 소비처별 혜택** |
| 상품 정보 | 금감원 오픈API (실데이터) | 카드사 자사 공시 수집 |
| 사용자에게 주는 것 | 실수령 예상 금리 | **예상 절약액** |

#### 왜 카드는 취향을 써도 되는가

저축에 취향을 쓰면 **없던 소비 목표를 만든다.** 카드는 반대로 **이미 하는 소비를 덜 나가게** 한다.

```text
X  "영화 좋아하시니 영화 적금 어떠세요?"        ← 목표를 새로 만든다 (R9 위반)
O  "이미 배달에 월 25만 쓰시는데, 이 카드면 연 9.6만 덜 나가요"
```

절약 서비스와 방향이 같다. 다만 선이 미묘해서 **표현을 강제한다.**

- 반드시 **사용자의 실제 소비 상위 카테고리**를 근거로 말한다(`회원님 지출 상위 2개 카테고리에 겹쳐요`).
- `이 카드로 배달 더 시키면 이득` 류의 **소비 증가를 전제한 문장은 금지**한다.
- 절약액은 **현재 소비를 그대로 유지했을 때**의 값이다. 늘렸을 때를 가정하지 않는다.

#### 절약액 계산

```text
예상 절약액 = Σ min(카테고리 월소비 × 할인율, 월 한도)      [전월실적 충족 시]
```

`카테고리 월소비`는 ③이 마이데이터에서 집계한 값(R10), 나머지는 카드 카탈로그 값이다.
전월실적을 못 채우면 혜택이 0이므로 **실적 충족 가능성도 함께 판정**한다.

#### 규제 — 저축보다 더 조심해야 한다

> 2021년 금융위·금감원은 플랫폼의 금융상품 비교·추천을 단순 광고가 아닌 **중개 행위**로 판단했고,
> **신용카드 추천도** `잠재고객 발굴·가입 유도 과정`으로 보아 문제 삼았다.

저축은 정보성 비교 예외(금융위·금감원 유권해석 2022.6.15)를 근거로 실 금리를 쓴다. **카드는 그 예외를 검증받은 적이 없으므로 더 보수적으로 간다.**

- 앱 안에서 발급·신청을 하지 않는다. `가입은 각 사로`.
- 제휴 링크·신청 폼·발급 편의 필드를 두지 않는다.
- 정렬은 **매칭 점수 순**이다. 광고비·제휴 순이 아니며, 화면에 그렇게 밝힌다.

#### 카탈로그 규모로 경쟁하지 않는다

카드 비교 서비스(예: 카드고릴라)는 카드사와 제휴해 1,500여 종을 유지한다. 수집으로는 그 규모를 따라갈 수 없고, 따라갈 이유도 없다.

```text
그들   1층(공시) + 2층(카드 혜택)          → "이 카드는 카페 5%"
우리   2층 + 3층(마이데이터 소비 흐름)     → "당신은 카페에 월 8만 → 연 4.8만"
```

**3층이 있어야 나오는 문장이 우리 자리다.** 카탈로그가 20~30장이어도 성립한다.

#### 데이터 출처

`scripts/collect-cards/` 참조. 요지만 적으면 —

- 여신금융협회 **카드다모아는 데이터 API가 403**이라 쓰지 않는다.
- **카드사 자사 공시** 중 `robots.txt`가 명시 허용한 곳만 수집한다(신한·KB·우리). **삼성은 `Disallow: /`라 제외**한다.
- 카드 부가서비스는 **3년 이상 유지 의무**가 있고 변경 시 **6개월 전 고지** 의무가 있다(신용카드 표준약관). 그래서 카탈로그가 빨리 낡지 않고, **재수집은 월 1회로 충분**하다.
- 혜택 문구를 우리 카테고리로 나누는 일은 자동화하지 않는다(§4.2 — 판단이 필요하다).

## 5. 취향 서술의 단계적 확장

취향은 한 번에 열지 않는다. **사실 → 패턴 → 취향** 순으로 넓힌다.

| 단계 | 서술 | 상태 |
|---|---|---|
| 사실 | "올해 영화 관련 소비가 32회 있었어요." | **MVP — 현재 여기까지** |
| 패턴 | "영화를 꾸준히 즐기는 편이네요." | 향후 |
| 취향 | "영화가 삶의 중요한 취미인 것 같아요." | 최종 |

MVP에서는 **취향 단정을 금지한다.** §3.3의 `올해의 영화 러버`는 집계 사실에 붙는 라벨이지 성향 단정이 아니다 — 32회라는 숫자가 함께 보이는 형태로만 쓴다.

## 6. 보류 — 은퇴(Retire)

초기 아이디어는 이랬다.

```text
"택시는 줄이기 어려운 필수 소비 같아요."  → 절약 후보에서 제외
```

**MVP에서 보류한다.** 시스템 판단이 들어가고, 잘못 분류될 위험이 있으며, 사용자가 평가받는 느낌을 받는다.

현재 허용 수위는 여기까지다.

```text
O  "택시는 최근 3개월 동안 큰 변화가 없었어요."
X  "택시는 줄이기 어려운 필수 소비예요."
```

그 이상의 의미 부여는 하지 않는다.

| 챌린지 상태 이름 노출 (`SHORTFALL`, `실패`) | 월간은 회고 (§3.2) |
| 행동 교정 (`줄여보세요`, `참아보세요`) | 거울이지 판단자가 아니다 (§1) |
