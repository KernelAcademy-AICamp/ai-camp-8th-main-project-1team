# 10. 카드 DB 구축 — 공시 원문에서 추천 후보까지

> 프로젝트명: MOA
> 문서 목적: 카드 추천의 **입력을 만드는 파이프라인**(수집·선정·추출·검산·적재)을 확정한다
> 상태: 표·적재 완료 · **수집 일단락(2026-08-18) — 578장 수집 · 카탈로그 561장 · 게이트 통과 86장(15.3%)**
> 최종 업데이트: 2026-08-18
> 담당: ③ 취향·추천
> 구현: `scripts/collect-cards/` · `service/CardCatalogLoader.java` · `db/migration/V34__card_product.sql`

판정이 **어떻게 도는지**는 `09_카드추천_판정.md`가 다룬다. 이 문서는 그 판정이 읽을 **표를
채우는 일**만 다룬다. 둘을 나눈 이유는 성격이 다르기 때문이다 — 판정은 사용자마다 매번 돌고,
이 파이프라인은 **한 번 만들어 두면 월 1회 갱신**이면 된다.

## 1. 단계

```text
카드사 자사 공시 (법정 의무 · robots.txt 허용)
        │
   D-1  수집          PDF 원문 → 저장소 밖(개인카드-로컬전용/)
        │
   D-2  후보 선정      법인·제한발급·특수결제 제외 + 2030 키워드 가점
        │
   D-3  LLM 이중 추출   PDF 전문 → JSON  (온도 0.0 / 0.2 두 번 → 대조)
        │
   D-4  게이트 3 검산   규칙 7종 → grade = PRECISE | REFERENCE
        │
   D-5  적재          card-catalog.json → 표 아홉(V34) · 기동 시 전량 교체
        │
        └─▶ 08 판정의 입력
```

| ID | 단계 | 구현 | 산출 | 상태 |
|---|---|---|---|---|
| D-1 | 수집 | `*_downloader.py` · `collector_policy.py` | PDF 원문 | ✅ 7개사 |
| D-2 | 후보 선정 | `select_youth_cards.py` | 후보 목록 | ⚠️ **BC 미적용** |
| D-3 | 추출 | `extract_llm.py` (Gemini) · `make_manifest.py` | `cards/*.json` | ✅ 578장 |
| D-4 | 검산 | `build_catalog.py` | `card-catalog.json` | ⚠️ 통과 86장(15.3%) |
| D-5 | 적재 | `CardCatalogLoader` | 표 아홉(`V34`) | ✅ |

**하지 않는 것**: 혜택 개정 추적(스코프 밖) · 카탈로그 전수 수집.

## 2. D-1 수집 — 1차 원천만 쓴다

| 후보 | 판단 |
|---|---|
| 여신금융협회 **카드다모아** | 데이터 API가 HTTP 403 — 운영자가 막아둔 것이라 **우회하지 않는다** |
| 금감원 통합비교공시 | 금융사가 신고한 값을 모은 **2차**. 신고 부실이 그대로 올라온다 |
| **카드사 자사 공시** | **채택.** 법정 공시 의무 정보이고 robots.txt가 명시 허용 |

지키는 것 — 호스트마다 `robots.txt`를 다시 읽고 **확인 못 하면 받지 않는다**. 요청 간격 1.5초,
동시 요청 없음, User-Agent에 목적을 밝힌다.

> **안전장치는 닫히는 쪽으로 실패해야 한다.** `RobotFileParser.read()`는 UTF-8로만 디코딩해서
> EUC-KR 주석이 있는 robots.txt에서 예외가 난다. 그걸 "파일 없음"으로 처리하면 **금지된 경로를
> 허용해 버린다** — 우리카드에서 실제로 발생했다. 직접 받아 `utf-8 → cp949 → euc-kr` 순으로
> 해석하고, 그래도 안 되면 건너뛴다. 404만 "제약 없음"으로 본다.

**재수집은 월 1회면 충분하다.** 부가서비스는 3년 이상 제공 후에만 변경 가능하고 변경 6개월 전
고지 의무가 있다(신용카드 표준약관). 혜택은 하루 단위로 안 바뀐다.

2026-08-12 확인 — 현대·하나·KB국민·NH농협 허용, **삼성은 전체 경로 불허**, 우리카드는 PC 목록만
가능(모바일 PDF 뷰어 불허), 롯데는 robots.txt 시간 초과로 중단.

## 3. D-2 후보 선정 — 전수를 하지 않는다

우리는 카드 목록 서비스가 아니라 개인화 추천이다(07 §4.4 "카탈로그 규모로 경쟁하지 않는다").
비싼 LLM 추출에 넣기 전에 **일반 사용자에게 추천할 수 없는 상품을 먼저 뺀다.**

| 제외 | 정규식이 잡는 것 |
|---|---|
| 법인·기업 전용 | 법인 · CORPORATE · 비즈 · BUSINESS · 사업자 · 구매전용 |
| 제한 발급 | 학생증 · 임직원 · 공무원 · 조합원 · 지자체 · 바우처 |
| 특수 결제 전용 | 주유전용 · 우편요금 · 지방세 · 유가보조 · 하이패스 전용 |
| 선불·기프트 | 선불 · 기프트카드 |

프리미엄 상품은 **제외하지 않고 감점**한다 — 고소득 사용자의 선택지를 남긴다.
점수는 추출 순서만 정하고 **사용자 추천 순위에는 쓰지 않는다.**

> ⚠️ **BC카드만 이 단계를 안 거쳤다.** `active` 전수 29장이 그대로 추출로 갔고 그중 **16장이
> 법인·특수결제**였다(법인 9 · 특수결제 7). 통과율 분모가 오염돼 있었다 — §6.

**발급중단 카드는 버리지 않는다.** 아직 그 카드를 쓰는 사용자의 혜택 비교에 필요하다.
표에는 남기되 `status=STOPPED`로 두어 추천 후보에서만 뺀다.

## 4. D-3 LLM 이중 추출

`pdftotext -layout`로 뽑은 **전문**을 통째로 넣는다.

> **grep 발췌 금지.** 상품설명서가 3단 편집이라 첫 매치 주변에 다른 칼럼이 섞인다.
> 실제로 이것 때문에 KaPick 실적 제외를 1개로 잘못 읽었다 — 12개였다.

```text
같은 PDF → 온도 0.0 로 1회 · 온도 0.2 로 1회 → numeric_projection 으로 대조
                                              → 다르면 numeric_consensus = false
```

**신원 칸은 모델에게 맡기지 않는다.** 이름·상품번호·게시일·출처 URL은 수집 메타데이터로
덮어쓴다(`apply_identity`). 모델이 지어낼 여지를 없애는 자리다.

**`as_of`는 여신금융협회 심의필 날짜만 인정한다.** `enforce_review_identity`가 `review_no`에
"여신금융협회"가 없으면 `as_of`를 `null`로 되돌린다. 준법감시인 날짜는 카드사 **내부** 검토
날짜라 다른 값이고, 그걸 심의필로 쓰면 "협회 심의 기준"이라고 거짓을 말하게 된다.

## 5. D-4 게이트 3 — 사람이 안 봐도 이상을 잡는다

| 규칙 | 걸리면 |
|---|---|
| `as_of` 없음 | 참고 |
| 실적 제외 항목 < 5개 | 참고 |
| 총연회비 ≠ 기본 + 제휴 | 참고 |
| 실적 구간이 오르는데 한도가 내려감 | 참고 |
| 한도의 구간 키가 `tiers`에 없음 | 참고 |
| 셈할 수 있는 혜택이 하나도 없음 | 참고 |
| LLM 이중 추출 불일치 | 참고 |

```text
문제 0건  →  PRECISE     숫자를 보여준다 · 추천 후보
1건 이상  →  REFERENCE   숫자를 안 보여준다 · 추천에서 뺀다
```

**빌드를 실패시키지 않는다.** 이유를 `gradeReason`에 적고 요약을 찍는다 — 한 장 때문에 전체가
멈추면 통과율을 못 잰다.

### 5.1 `countable` — 이 단계의 핵심 판단

| 못 세는 이유 | 뜻 |
|---|---|
| 금액 환산 불가 | 무이자할부 · 라운지 · 발렛파킹 |
| 요율·정액이 없다 | `rate_percent`도 `amount_krw`도 비어 있다 |
| 승인내역에서 고를 대상이 없다 | 브랜드도 업종축도 없어 매칭할 수 없다 |

`countable=false`는 **혜택이 없다는 뜻이 아니라 금액으로 셀 수 없다는 뜻**이다.
표시는 하고 절감액에서만 뺀다.

## 6. D-5 적재 — 기동할 때 전량 교체

카드는 사용자 데이터가 아니라 **앱의 상수**다. 시드 API에 두면 "시드를 돌렸는가"에 따라 화면이
달라진다(실제로 `financial_product`가 비어 추천 화면이 빈 채로 있던 적이 있다). 리소스로 함께
배포하고 기동 시 넣으면 **어느 환경에서 켜도 같은 카드가 나온다**.

**매번 지우고 다시 넣는다.** 카탈로그가 원천이고 표는 파생이라, 부분 갱신을 상정하면 원천에서
사라진 혜택이 표에 남는다. `ON DELETE CASCADE`로 딸린 행이 함께 사라져 유령 행이 안 생긴다.

**이 단계는 판정하지 않는다.** `grade`·`countable`은 D-4가 이미 정했고 그대로 옮겨 적는다.
검산을 두 곳에 두면 갈라진다.

표 아홉 — `card_product` · `card_annual_fee` · `card_performance_rule` · `card_performance_tier` ·
`card_exclusion` · `card_benefit` · `card_benefit_cap` · `card_combined_cap` · `card_benefit_target`.

## 8. 막힌 곳

### 8.1 스키마가 카드사 표를 못 담는다 (가장 근본)

`Young Hana 체크카드` 실측 — 대상은 완벽히 뽑혔는데 요율이 통째로 비었다.

```text
group='하나머니 적립 서비스'   rate_percent = null
   커피 → 스타벅스 | 편의점 → GS25 | 영화 → CGV·롯데시네마·메가박스
   외식 → 아웃백·VIPS | 쇼핑 → 11번가·쿠팡·티몬 | 통신 → SKT·KT·LGU+
```

원문에는 **대상마다 다른 요율**이 있다(스타벅스 20% · GS25 10% · CGV 10% · 아웃백 5%).
그런데 스키마는 `rate_percent`를 **혜택 묶음에** 두고 `targets[]`에는 두지 못한다.
모델은 넣을 자리가 없어 `null`로 뒀다 — "추측하지 말라"는 지시를 지킨 결과다.

BC 3장에서 안 드러난 이유는 셋 다 **묶음마다 요율이 하나인 카드**였기 때문이다.
`V34` 머리말의 *"스키마가 흔들릴 축은 이미 다 드러났다"*는 **같은 카드사 표 양식 안에서만** 참이었다.

> **고칠 곳** — `targets[]`에 `rate_percent`·`amount_krw`·월한도를 허용하고, 비면 묶음 값을
> 물려받게 한다. 묶음 단일 요율인 카드는 지금과 똑같이 동작한다.
> `V34`·`CardBenefitTarget`·`extract_llm.py` 스키마가 함께 바뀐다.

### 8.2 게이트 임계가 3장 표본 기준

`실적 제외 <5 → 참고`는 KaPick 사고를 잡으려 만든 규칙인데 근거가 **BC 신용카드 3장**이다.
**561장 중 145장(26%)이 여기 걸린다** — 표본이 여섯 배로 늘면서 비중도 함께 커졌다.
3장으로 정한 임계가 561장을 재단하고 있으니, 이제 역산할 재료는 충분하다.

### 8.3 ~~KB국민카드 18장 전멸~~ — 표본 문제였다 (2026-08-18 해소)

18장에서 0장이라 "한 카드사만 전멸하니 원인이 하나"라고 봤는데, **387장으로 늘리자
49장이 통과했다(12.7%)**. 전멸이 아니라 표본이 작아 0이 나왔던 것이다.

다만 **여전히 최하위**다. 소량 카드사가 25~32% 인데 KB는 12.7% · 현대는 13.8% 로,
장수가 많은 쪽이 낮다. 원인은 카드사가 아니라 **선정 없이 대량으로 밀어 넣은 것** 쪽으로
보인다 — 소량 카드사는 D-2 로 걸러진 목록이다. 확인 전까지는 추정이다.

### 8.4 곁가지로 확인된 것

| 확인한 것 | 결과 |
|---|---|
| `as_of` 없는 168장 | **버그 아님.** 원문에 여신금융협회 심의필 문구가 없다(8/12 당시 33장 전수 대조) |
| `category` 189종 | 스키마가 `string`이라 모델이 매번 이름을 지어냈다. 정본 21축과 일치하는 건 10종뿐 |
| 별칭 표 효과 | `axis-aliases.json`으로 189종 100% 분류. **통과 장수는 안 바뀐다**(13→13) — 매칭 정확도(+12행)에 기여 |
| 불일치 336건의 성격 | `category` 62건 + `group` 45건이 **이름 표현 차이**(`카페` vs `커피`). 진짜 숫자 불일치는 `rate_percent` 16 · `requires_tier` 24 |

| 나머지 카드사 추출 | ③ | 삼성 25 · 현대 87 은 들어왔다. **남은 것은 신한·롯데·농협** |
| 16,253건 전수 여부 | ③ | 통과율이 정리된 뒤 판단. **장수보다 구성 균형이 먼저다**(§7 ⚠️) |
| `as_of` 없는 카드의 표기 | 기획 | 참고 모드로 두거나, "수집일 기준"으로 낮춰 표기하거나 |
