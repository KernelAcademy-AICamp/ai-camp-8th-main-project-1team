## 데이터 파이프라인 — 팀 간 데이터 주고받기

- **프로토콜 = 포맷이나 규격을 미리 정해두는 것**
    - 원래 개발에서는 데이터 포맷을 먼저 정의하고 시작하지만, 바이브 코딩에서는 별도 정의 없이 "이런 포맷으로 넘길게" 수준으로 진행하게 됨
- 분업 중이지만 하나의 서비스를 함께 보고 개발하는 구조 → 각 산출 결과에 대한 논의 지속 필요
- 넘어온 데이터와 실제로 쓰려는 데이터 사이 간극 발생은 불가피 → 상시 조율 대상
    - LLM이 만들어준다고 끝나는 게 아니라 사이사이 사람의 손질이 필요
- 협업의 기본은 **데이터 포맷 공유** — "내가 어떤 결과를 어떤 형태로 넘긴다"를 먼저 명확히 공유
    - 이후 쓰는 쪽에서 불편하거나 구멍이 있으면 바로바로 얘기하며 수정
    - 활용하는 쪽에서만 보이는 문제가 많으므로 분석 쪽 단독 판단 지양
- 논의할 게 많으면 매일 오후 고정 시간에 업무 정리 미팅을 잡는 것도 방법
- 자체 DB 구축 권고 사항 이행 완료 → LLM 왕복 대비 속도·비용 개선

## 중간 데모 시연 방식

- 현재 AWS 배포본은 초록색 디자인 초기 버전 상태 (이후 업데이트 미반영)

- 다만 실제 사용 중인 카드 소비 데이터가 결과에 반영되는 모습을 보여주는 게 설득력 있다는 의견(이상현)

    - 내일까지 적용 가능 여부는 미확정

## 화면 플로우 정리 (진입 ~ 소비 요약)

- 앱 진입 → 스플래시 → 온보딩 여부 분기
    - 온보딩 전: 서비스 소개 슬라이드 → 본인 인증 → 마이데이터 연결 → 내역 불러오기
    - 온보딩 후: 내역 불러오기 → 홈
- 챌린지 상태 분기: 진행 중 / 챌린지 없음 / 종료(한 달 완료) → 월말 결산
    - '챌린지 없음' = 지킬 돈을 아직 설정하지 않은 상태
    - 최초 1회에만 노출되며, 이후에는 진행 중 또는 월말 결산으로만 진입
- 성역 설정은 매달 새로 진행
- 화면별로 무엇을 보여줄지 팀에서 한 번도 정리한 적 없다는 점 확인 → 이번 회의의 목적으로 설정

## 월간 리포트(소비 요약) 구성

- 현재 첫 화면은 월평균 상위 카테고리만 노출 → 정보가 지나치게 압축되어 파악 어려움
- 개선 방향(이가원 제안)
    - 지난 3개월 평균 총지출 금액 제시 → 그중 절약 가능한 금액(세는 돈) 제시 → 하위에 카테고리 배치
    - '지난 3개월'이라는 표기 방식 자체도 손볼 필요
- 일반 핀테크 가계부 관행: 총지출 → 고정비 / 변동지출 → 변동지출 카테고리 세부
    - 고정비 기준 = 반복 지출 (구독료·월세·공과금·전화비 등)
- 우리 서비스에는 규칙성 축이 맞지 않음 — 잘 안 보는 넷플릭스라면 고정비여도 낭비 → **낭비 여부 판정이 우선**
    - 참고로 이가원 실데이터는 고정비가 구독료뿐이라 판단 근거로 삼기 어려움
- 혼선 지적(이상현)
    - 총 지출 금액과 낭비 금액이 달라 숫자가 헷갈림
    - 많이 쓴 카테고리와 낭비 많은 카테고리가 서로 다름 (교통비는 지출이 커도 줄일 항목 아님)
- 해결 방향: 카테고리별 소비 그래프 **안에서** 낭비 해당분만 컬러로 구분 표시 → 기존 소비 안에 세는 돈이 얼마인지 한눈에 파악
    - 이후 흐름: 세는 돈 확인 → 줄일 항목 선택 → 전체 또는 일부 금액 선택 → 설정 완료
- 미결: 소비 요약 첫 화면의 표현 방식은 계속 고민 필요

## 소비 분석 에이전트 동작 로직

- 소비 내역 투입 → **카테고리 분류**(식비·카페·편의점·대형마트 등) → 카테고리 내에서 **낭비 여부 판정**
- 3개월치 내역을 먼저 읽어 카테고리별 평균 금액 산출
- 이 로직 중 월 지출 리포트에 노출 가능한 구간과 아닌 구간을 구분할 필요

## 카테고리 분류 정확도 이슈

- 전반적으로는 분류가 잘 되는 편이나 오분류 확인
    - 티머니(모빌리티)가 쇼핑으로 분류
    - 카카오 관련 결제가 다수 쇼핑으로 분류
- 수동 변경 시 DB는 업데이트되나, 같은 가맹점 건들이 일괄 **재분류되지 않는 문제** 확인 → 해결 필요
- 교통 하위(택시·KTX 등)는 교통·자동차로 통합 표기되며, 교통은 보통 낭비가 아니므로 순위 하단 배치
- 사용자에게 재량 소비 여부를 되묻는 기능은 미구현 (현재 질문은 "LLM 분류가 맞나요?" 확인뿐)

## ✅ 결정사항

- 중간 데모는 AWS 시연이 아닌 **화면 녹화 영상**으로 진행 확정 → AWS 재업로드 불필요
- 데모에 실제 사용 소비 데이터를 반영해 보여주는 방향으로 합의 (적용 시점은 미확정)
- '챌린지 없음' 상태는 최초 1회에만 노출되는 것으로 정리
- 월간 리포트는 규칙성(고정비/변동비) 축이 아닌 **낭비 여부 축**으로 구성하는 방향 재확인
- 카테고리 그래프 내 낭비분 컬러 구분 방식을 표현 후보로 채택
- 중간 데모의 핵심 설명 파트를 소비 분석 에이전트 로직으로 확정
- 세부 화면 사항은 각자 조사 후 다음 주 논의로 이월
