## 1. 지난 멘토링 이후 변경사항 공유

- 회원가입·온보딩 플로우 순서 변경 완료
- 온보딩 단계의 AI 질문(사용자 맥락 파악용)은 설계 미비로 아웃 오브 스코프 처리
  - 사용자 맥락 파악 방법 자체가 오늘의 주요 질문 안건으로 이동
- 더미 데이터 기반 카테고리 분류 로직 정리 완료 → 오늘 공유
- 마이룸(게이미피케이션)은 우선순위에서 후순위로 조정
  - 키 기능은 마이룸보다 '새는 돈을 지키게 돕는 것'이라는 판단 (멘토: 합리적 판단)
- 월간 리포트 와이어프레임 정보 위계 정리 진행 중
- 화면상 변화보다 백엔드 처리 개선이 중심인 버전 (멘토: 그게 핵심)
- AWS 배포 완료, 무료 도메인(3개월) 사용 중 — 비용 최소화 기조

## 2. 온보딩 첫 화면 / 첫 월간 리포트 구성

- 신용정보 수집·이용 동의 필수 여부 이슈
  - 타 핀테크 앱은 선택 항목으로 운영 중, 현행법 확인 필요
  - 양식·구색 맞추기 목적으로 들어간 항목임을 인정, 현재는 크리티컬하지 않아 유지
- 카테고리 선택으로만 화면을 끌고 가는 구조가 유저가 원하는 리포트 체계에 맞는지에 대한 고민 제기
  - 멘토: 이 화면에서 어떤 밸류(충격 / 유용함 / 낭비 자각)를 줄지 먼저 정하고 구성할 것
- 금액만 보고는 판단이 어렵다는 지적
  - 25만 원이 어떤 지출(치킨·피자 등)로 구성됐는지 봐야 줄일 수 있는 지출인지 판단 가능
  - 낭비로 예상되는 지출 내역을 먼저 띄우고, 해당 없는 항목 체크 해제 시 금액 연동 조정되는 구조 확인
- 인풋 과다 우려 vs 참고용 유지 의견
  - 카테고리를 일일이 펼쳐 체크해야 하는 부담 지적
  - 멘토: 접어두면 되는 구조이므로 참고용 수준으로 유지 무방, 꼼꼼한 사용자만 열어볼 것
  - 전체 내역이 아닌 **낭비 판정 건만** 노출하는 현행 방식 유지로 정리
- 절약 강도는 퍼센트 조절(기본 50%) 방식이며, 대략적 금액 입력 방식도 검토 여지

## 3. 낭비 판정 로직

- 판정 기준
  - 마이데이터로 들어온 몇 달치 데이터에서 카테고리별 개인 평균 산출
  - 평균 대비 2~3배 이상 지출 → 낭비 판정 (가장 큰 지표)
  - 평소 활동 시간대와 다른 결제(주간 활동자의 심야 배달 등) → 변동성 지수로 판정
- 기간 기준 불일치 논점
  - 소비 패턴 파악 3개월 평균 vs 차감 기준 1개월 데이터
  - 3개월 기준 시 리스트가 길어지는 문제로 1개월로 조정된 상태
- 식비 낭비 판정의 모호함 (아침·점심은 필수, 오후 3시 간식은 애매) — 시간 기준은 겸용 지표로 사용
- 결론: 모든 데이터를 화면에 다 보여줄 필요 없음, 초기 컨셉 기준으로 압축

## 4. 카테고리 분류 구조 (소비 분석 에이전트)

- 기본 흐름
  - 자체 사전 DB(사업자번호 + 가맹점명 + 국세청 업종코드 6자리) 조회
  - 미등록 건은 LLM에 판정 요청 (세분류 목록을 40개씩 묶어 전달)
  - LLM 판정 건은 태그를 달아 저장, 사용자 확정 또는 수정 시 사전에 합류 → DB 누적
- 예외 처리
  - PG사 이슈: 사업자번호는 KT모빌리언스, 가맹점명은 삼성물산 등 불일치 다수 → PG사 목록 별도 구성, 가맹점명으로만 조회
  - 복합사업자 개념 신설: 같은 사업자번호에 가맹점명이 다른 경우(택시, 울릉크루즈 내 GS25 등)
  - 같은 중분류로 5건 이상 반복 분류되면 복합사업자 → 단일사업자로 전환
- 분류 체계 변경
  - 자체 중분류 15개 기준 판정 시 오분류 발생(올리브영 → 쇼핑/화장품/편의점 혼선)
  - 국세청 세분류 투입 시 '화장품 판매업 → 미용' 정확 분류 확인 → 업종 분류 채택
  - 넷플릭스 등 구독 서비스는 업종코드상 3개 업종이 묶여 있어 분류 난항
- 멘토 평가: 핀테크에서는 앱 UI보다 이 영역이 더 중요, 정상적인 방향으로 진행 중

## 5. 사용자 맥락 파악 / 개인화 (미결)

- 문제: 범용 기준으로 낭비를 판정 중이나, 개인화하려면 사용자 맥락 필요
- 검토 중인 수집 경로 — 온보딩 질문 / 기존 소비 패턴 / 결제 시점 푸시 확인
- 멘토 의견
  - 맥락은 사용자만 알기 때문에 '받아야' 하며, 덜 귀찮게 잘 받는 방법이 핵심
  - 답은 없고 페르소나 대입 + 테스트로 찾아가야 하는 영역
  - 앱 설치 + 마이데이터 연동까지 한 유저는 의지가 강한 편이며, 의지는 초반에 가장 높음 → 초반에 어느 정도 받아둘 것 (단, 온보딩 부담은 최소화)
- 푸시 관련 논의: 토스 사례(하루 20개), 푸시의 이득과 이탈 손해 사이의 선을 설계로 잡아야 함
- 초개인화 확장 아이디어: 포장 시 할인 안내, 편의점 대신 마트 제안 등
  - 단, 브랜드 대체 제안(스타벅스 → 메가커피)은 브랜드 가치를 무시할 수 있어 조심스러운 영역

## 6. 리포트 구조 재설계

- 현재 주간 리포트 초안 구성: 주별 지킨 금액, 요일별 남은 돈·쓴 돈, 카테고리별 세부 내역, AI 요약(잘한 점·살펴볼 점), 다음 주 미션, 챌린지 달성률(배지)
- 개선 논점
  - 지킨 금액과 쓴 금액은 맥락이 반대 → 목표 금액을 함께 노출해야 모니터링 가능
  - 리포트 탭과 홈 탭의 핵심 경험 중복 (목표·퍼센테이지·카테고리·소비 내역이 UI만 다르고 동일)
- 정리된 방향
  - 월 단위를 기준으로 두고 그 안에 주간을 세부로 배치 (토스·뱅크샐러드 가계부 구조 참고)
  - 명칭도 '리포트' 대신 '내 소비' 형태 검토 (모니모 참고)
  - 홈 = 오늘·지금 현황 / 리포트 = 앞으로의 방향 설정
  - 또래 비교 등 인사이트 항목 추가
- 또래 비교 관련
  - 압박감(페인 포인트)을 이유로 제외했으나, 멘토는 '쓰는 돈에 대한 압박은 필요한 압박'으로 판단 → 반영 방향
- 카드 추천 배치
  - 매주 노출 시 금융상품 반복 노출 규제 이슈 + 카드 교체 주기와 불일치
  - 주간 → 월간 리포트 하단으로 이동
  - 멘토: 비즈니스 모델로도 사용자 맥락으로도 적합, 문구를 절약 맥락으로 더 구체화할 것
- 신규 사용자 기준 시점
  - 앱 설치 이전 데이터까지 모두 불러와 표시하는 방향
  - 다이어트 비유(결심 전 폭식도 인지해야 더 아끼게 됨), 챌린지 전 주 금액과 비교 가능해지는 이점
- 마이룸 보상 아이디어: 소품 외 명언·응원 문구 등 의지를 북돋는 요소 (멘토 참고 의견)

## 7. 홈 구성 확인

- 현행 구성(최근 소비, 남은 예산, 마이룸, 현황) 유지
- 더 넣으면 복잡도만 증가한다는 판단
- 스크롤 유도를 위해 화면 하단을 일부러 잘리게 두는 방식도 유효

## 8. 협업 방식 / 개발 프로세스

- 현황: 3인 각자 에이전트 개발 중
  - 이상현 — 지킴이 에이전트 + 프론트엔드
  - 이가원 — 전체 조율 + 금융상품 추천 에이전트
  - 지윤정 — 소비 분석 에이전트
- 문제: 에이전트 간 주고받는 데이터가 물려 있어 중복 작업·미수신 발생, 기능 단위 분리가 어려움
- 대응: 다음 주 월요일 데이터 프로토콜 정리 예정
- 멘토 조언
  - 하루 1~2회 스크럼으로 진행 상황 싱크 (형식적 데일리일 필요 없음)
  - 바이브 코딩은 아웃풋이 빠른 만큼 중복도 늘어나므로 더 긴밀한 소통 필요
  - 겹칠 것 같은 지점은 그때그때 협의해 진도 빠른 쪽이 먼저 진행
