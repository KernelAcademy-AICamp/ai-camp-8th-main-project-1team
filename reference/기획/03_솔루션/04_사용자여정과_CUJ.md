## 1. User Journey

### 1.1 대상과 목적

**대상 사용자**

> 스트레스 때문에 배달·쇼핑·택시를 이용한 뒤 후회하지만, 무엇을 줄여야 할지 몰라 절약을 오래 이어가지 못하는 20~30대 직장인

**사용자가 이루려는 진전**

> 후회하는 소비를 후회하지 않는 소비로 바꾸기 위해, 무엇을 줄일지 판단하고 이번 달 지키기로 한 돈이 실제 소비 속에서 얼마나 보호되고 있는지 알고 싶다.

고객의 문제·욕구는 `01_고객/03_타깃고객.md`와 `01_고객/04_문제정의.md`를 따른다. 아래 표에서 서비스 진입 이후의 감정은 아직 실사용 검증 전인 **경험 가설**이다. 사용자 인터뷰와 사용성 테스트 전에는 고객 사실로 인용하지 않는다.

### 1.2 전체 여정 지도

| 단계 | 사용자 목표·행동 | 주요 접점 | 예상 감정 | 핵심 마찰·이탈 위험 | MOA의 대응 | 단계 완료 신호 |
|---|---|---|---|---|---|---|
| **0. 문제 인지** | 카드값·결제 내역을 보고 후회한다. 무엇을 줄여야 할지 모르겠다고 느낀다 | 카드 명세서, 금융 앱, 배달·쇼핑 앱, 주변 추천 | 후회·막막함·자책 | 문제를 알아도 가계부나 전면 금욕을 다시 시작하고 싶지 않다 | “전체 소비 통제”가 아니라 “내가 고른 소비에서 지킬 돈”이라는 가치 제안 | 자신의 문제를 `무엇을 줄일지 모름`과 `중간 성과가 안 보임`으로 인식 |
| **1. 발견·판단** | MOA가 또 다른 가계부나 잔소리 앱인지 판단한다 | 서비스 소개, 온보딩 가치 소개 | 경계·호기심 | 차별점이 바로 이해되지 않거나 금융정보 연결 비용이 더 크게 느껴짐 | 가치 소개를 한 장으로 제한하고, 자동 분석→사용자 선택→지킬 돈의 관계를 설명 | 연결을 시작하거나 이탈 이유가 식별됨 |
| **2. 신뢰·연결** | 동의 범위와 연결 이득을 확인하고 카드·계좌를 연결한다 | 전송요구 동의, 통합인증, 기관·계좌 선택, 수집 진행 | 불안·귀찮음·기대 | 개인정보 불안, 90일치 초기 수집 대기, 필수 연결로 인한 중도 이탈 | 동의 이유·수집 범위·진행률을 설명하고, 대기 중 성역을 지정하게 함. 이탈 후에는 저장 상태에서 재개 | 필요한 데이터 수집 완료 |
| **3. 첫 가치** | 분석 근거를 보고 건드리지 않을 소비와 줄일 소비를 직접 고른다. 강도를 선택해 지킬 돈을 확정한다 | 분석 결과, 성역, 절약 후보, 카테고리·강도 선택, 확정 화면 | 놀람→납득→통제감·안도 | 추천 불신, `지킬 돈`을 잔액·예산으로 오해, 지나치게 높은 목표 선택 | 추천은 후보로만 제시하고 최종 선택권을 사용자에게 둔다. 확정 전 금액 근거와 난도를 설명 | **지킬 돈 확정 후 Home 진입 — 활성화 완료** |
| **4. 월중 지킴** | 별도 기록 없이 현재 지키는 금액을 확인하고, 필요할 때만 분류를 바로잡는다 | Home, 거래 내역, 초과 알림, 맥락 태그, 오분류 수정 | 평온·안심 또는 초과 시 아쉬움 | 자동 분류 불신, 잦은 알림이 감시·비난으로 느껴짐, 차감 이유를 이해하지 못함 | 선택 카테고리만 추적하고 한도 안에서는 침묵. 초과분만 차감하며 원인 거래와 복구 경로를 제공 | 거래가 정상 반영되고 사용자가 현재 금액과 변동 이유를 설명할 수 있음 |
| **5. 월말 회고** | 이번 달 최종 지킨 돈과 소비 맥락을 확인한다 | 월말 결산, 월말 리포트, 성장 연출, 마이룸 | 성취·안도 또는 실망 | 0원·낮은 성과를 실패나 퇴화로 느끼면 이탈 | 지킨 금액 중심으로 비난 없이 회고한다. 이미 쌓인 성장과 소품은 깎지 않는다 | **월말 확정 결과와 성장 확인 — 핵심 가치 완결** |
| **6. 반복·이탈** | 다음 달에도 이어갈지 판단하고 카테고리·강도를 다시 정한다 | 다음 달 지킬 것 정하기, 새 챕터, 재진입 Home | 자신감·새 출발 또는 피로·무관심 | 같은 목표 반복, 달성 불가능한 추천, 월말 리포트 미확인 | 지난달 결과를 바탕으로 다음 달 선택을 다시 사용자에게 맡기고 누적 성장은 유지 | 다음 달 챕터 시작 또는 이탈·휴면 사유 식별 |

### 1.3 감정 흐름 가설

```text
후회·막막함
→ 경계·호기심
→ 연결 과정의 불안·귀찮음
→ 분석 결과에 대한 놀람·납득
→ 직접 선택했다는 통제감
→ 월중의 조용한 안심
→ 월말 성취 또는 실망
→ 다음 달 재도전 또는 이탈
```

이 감정선은 화면 문구의 목표이지 검증 결과가 아니다. 특히 다음 세 지점은 우선 검증한다.

1. 필수 마이데이터 연결의 이득이 불안과 수고보다 크게 느껴지는가
2. `지킬 돈`을 잔액·예산·저축액과 구분해 이해하는가
3. 초과 차감과 알림을 비난·감시가 아니라 설명 가능한 도움으로 받아들이는가

### 1.4 주요 이탈과 재진입

| 이탈 지점 | 관찰할 이유 | 재진입 원칙 |
|---|---|---|
| 가치 소개 전후 | 서비스 차별점 불명확 | 다시 가치 소개부터 시작 |
| 동의·인증·기관 선택 | 개인정보 불안 또는 절차 부담 | 연결 안내로 복귀하고 동의 범위를 다시 설명 |
| 90일치 초기 데이터 수집 중 | 대기 시간·진행 불확실 | 저장된 수집 상태와 성역 선택에서 이어서 시작 |
| 분석·카테고리 선택 | 추천 불신 또는 적절한 후보 부족 | 분석 결과부터 다시 확인하고 성역 조정 가능 |
| 월중 | 자동 분류 불신·알림 피로·효용 부족 | Home에서 현재 지키는 금액과 변동 근거를 우선 제시 |
| 월말 | 낮은 성과·리포트 가치 부족 | 결과를 비난하지 않고 다음 달 강도 재선택으로 연결 |

앱 내부의 정확한 복귀 화면은 `04_스펙/01_prd.md` §12.3과 `04_스펙/04_IA.md`가 정본이다.

## 2. Critical User Journey

### 2.1 공식 CUJ 한 문장

> **사용자가 이번 달 줄일 소비와 강도를 직접 정해 `지킬 돈`을 만들고, 실제 거래의 자동 반영을 거쳐 월말에 확정된 `지킨 돈`과 성장을 확인한다.**

### 2.2 CUJ 경계

| 항목 | 공식 정의 |
|---|---|
| 사용자 목적 | 무엇을 줄일지 정하고, 실제 소비 속에서 지키기로 한 돈이 얼마나 남았는지 확인한다 |
| 서비스 가치 | 과거 소비 분석을 사용자의 선택으로 바꾸고, 그 선택을 실제 거래와 연결해 월말 결과로 확정한다 |
| 단위 | **달력 월 1개 챕터**. 첫 달만 가입일 기준 일할 계산 |
| 진입 | 첫 달: 마이데이터 수집·분석 완료 / 다음 달: 이전 월 리포트에서 `다음 달 지킬 것 정하기` 선택 |
| 활성화 지점 | 카테고리·강도 선택 후 `지킬 돈` 확정, Home 진입 |
| 가치 완결 지점 | 월말 `지킨 돈` 확정 후 리포트와 성장 결과 확인 |
| 반복 연결 | 다음 달 카테고리·강도 재확정 후 새 챕터 시작 |

**활성화와 가치 완결을 구분한다.** `지킬 돈`을 확정한 것은 서비스 사용 준비가 끝난 상태다. MOA의 약속은 실제 소비로부터 돈을 지키는 것이므로, 거래 반영과 월말 확정 결과를 확인해야 핵심 가치가 완결된다.

### 2.3 대표 성공 경로

```text
[첫 달 선행 조건]
마이데이터 연결·수집 완료
        ↓
AI 분석·절약 후보와 근거 확인
        ↓
성역 확인(첫 달) → 줄일 카테고리 선택 → 강도 선택
        ↓
지킬 돈 확정 → Home                         ★ 활성화
        ↓
선택 카테고리의 실제 거래 자동 분류·누적
        ├─ 사용 한도 이내: 지킬 돈 유지 · 침묵
        ├─ 사용 한도 초과: 초과분만 차감 · 이유 안내
        └─ 오분류·취소·환불: 수정·재계산·복구
        ↓
월말 원장 마감 → 최종 지킨 돈 확정
        ↓
월말 리포트·성장 확인                       ★ 핵심 가치 완결
        ↓
다음 달 지킬 것 재선택 → 새 챕터             ↺ 다음 CUJ
```

선택 카테고리의 거래가 한 건도 없는 달도 유효한 경로다. 거래 유무와 관계없이 월말 원장을 마감하고 결과를 설명할 수 있어야 한다.

### 2.4 필수 분기와 실패 처리

| 상황 | CUJ 원칙 |
|---|---|
| 마이데이터 연결 거부·미완료 | 분석 근거가 없으므로 CUJ에 진입시키지 않고 연결 안내를 유지 |
| 성역 제외 후 후보 부족 | 성역 해제를 강요하지 않고 조정 선택지를 설명 |
| 카테고리 미선택 | 지킬 돈을 만들 수 없으므로 확정 불가 |
| 과도한 카테고리·강도 선택 | 달성 난도를 경고하되 사용자의 최종 선택을 막지 않음 |
| 한도 이내 소비 | 불필요한 알림 없이 지킬 돈 유지 |
| 한도 초과 소비 | 초과한 금액만 차감하고 원인 거래를 설명 |
| 오분류·취소·환불 | 원장을 재계산하고 변동·복구 이유를 확인 가능하게 함 |
| 월말 지킨 돈 0원 | CUJ는 정상 완료. 실패·퇴화·소품 회수 없이 다음 달 재선택 제공 |
| 월말 리포트 미확인 | 핵심 가치 미완결로 집계하고 재진입 시 결과 확인으로 복귀 |

### 2.5 성공 측정

CUJ는 다음 네 단계로 측정한다. 수치 목표와 이벤트 구현은 `04_스펙/01_prd.md` §16 및 분석 설계에서 관리한다.

| 단계 | 대표 지표 | 의미 |
|---|---|---|
| 진입 | 마이데이터 연결 완료율 | 핵심 가치를 받을 데이터 준비가 됐는가 |
| 활성화 | 온보딩 완주율·카테고리 선택 완료율 | 사용자가 지킬 돈을 직접 만들었는가 |
| 신뢰 가능한 전달 | 거래 자동 반영 성공률·차감 이유 설명 가능 응답·오분류 수정률 | 실제 소비가 정확하고 이해 가능하게 반영됐는가 |
| 가치 완결·반복 | 월말 성장 확인률·다음 달 챕터 시작률 | 한 달의 결과를 확인하고 다음 사이클로 이어졌는가 |

**CUJ 완료의 대표 지표는 `월말 성장 확인률`이다.** `다음 달 챕터 시작률`은 가치 완결 이후 반복 사용을 보여주는 후행 지표다.

### 2.6 CUJ에 포함하지 않는 기능

다음 기능은 유용하지만 없어도 핵심 가치 전달은 완결되므로 대표 CUJ에 포함하지 않는다.

- 주간 리포트와 상세 소비 탐색
- 마이룸 도감·포인트샵 탐색
- 맞춤 카드·금융상품 정보성 비교
- 연결 기관·성역·지킴이 말수 등 설정 관리
- 데모 패널과 관리자 화면

이 기능들은 CUJ의 **이해·신뢰·동기·반복**을 돕는 보조 접점으로 관리한다.

### 2.7 CUJ에서 확인한 설계 과제와 결론 (2026-08-20)

여정을 시간축으로 펴자 CUJ 안에서 세 가지가 드러났다. 셋 다 결론이 났으므로 미해결로 두지 않는다.

#### ① 성공의 인지 — 성공은 사건이 아니다

사용자가 절약을 실감하는 순간은 **쓰지 않은 순간**이다. 그런데 쓰지 않음은 거래를 남기지 않으므로, **그 순간에는 성공했는지 알 방법이 없다.** 실시간 격려는 원리상 불가능하다.

> **결론.** 하루를 마감하는 시점에 선택 카테고리의 지출 발생 여부를 확인해 판정한다. 거래 시점이 아니라 **일 마감 배치**가 격려를 낸다.

**문턱은 사람마다 다르다 (2026-08-20).** v1.5는 누구에게나 무지출 3일을 요구했는데, **매일 밤 배달을 시키던 사람에게 3일 연속은 거의 불가능**하다. 하루 참은 것이 그 사람에게는 큰 성과인데 아무 반응이 없었다 — **절약 폭이 가장 큰 사용자가 격려를 가장 못 받았다.**

> **개정.** 최근 4주 중 그 카테고리에 결제가 있었던 일수로 문턱을 정한다. 거의 매일 사던 사람은 **무지출 하루**면 격려한다. 규칙은 `06_지킴이_Agent_설계.md` §3.4가 정본이다.

**하루가 지나기 전에 보낸다.** 22:00 야간 금지 앞에서 판정해 `오늘`이라고 말한다. 그 사람이 평소 쓰던 시간대가 지난 뒤가 판정 시점이다(§3.4.1). 판정 뒤에 결제가 들어와도 **보낸 격려를 회수하지 않는다.**

**남는 것은 도달 여부다.** C5·C10을 8·9위로 올리고 쿨다운을 일 1회로 풀었지만, 하루 푸시 2건 예산의 시간성 슬롯 1칸을 W1·M1과 나눠 쓴다. 특히 **아침 세리머니(M1)와 내용이 겹치는 문제는 미해결**이다(`06` §9.2). 격려가 실제로 몇 번 나가는지는 측정 대상이다(`01_prd.md` §21.2).

#### ② 결산 노출 — 결산일과 사용자의 월말이 다르다

사용자가 소비를 실감하는 날은 카드 결제일인데, 결산은 달력 말일에 난다. 대표 지표인 `월말 성장 확인률`이 **하필 앱을 열 이유가 가장 없는 날**에 걸린다.

> **결론.** 결과는 해당 달의 마지막 날(28·30·31일)에 확정해 보여주되, **리포트 탭 상단에 결산 배너를 상주**시킨다. 배너는 **다음 챌린지 설정 전까지** 유지한다.

챌린지 경계(달력 월)는 옮기지 않는다. **노출 기간만 늘려** 언제 열어도 결과에 닿게 한다. 화면 정의는 `04_스펙/04_IA.md` RP-02A가 정본이다.

#### ③ 지킨 돈의 실재 — 이번 스코프 밖

지킨 금액이 화면 안 숫자로만 남으면 **다음 달에 또 쓸 돈과 구분되지 않는다.** 본래 해법은 지킨 돈을 실제 계좌로 옮기는 것이다.

> **결론.** 계좌 이체는 이번 프로젝트 업무 범위를 넘어서므로 **구현하지 않는다.** 그때까지의 대체 동기는 마이룸이다.

새로운 소비 목표를 만들지 않겠다는 원칙(`02_솔루션컨셉.md`)은 유지한다. `FP-01` 맞춤 금융상품 추천은 이 문제의 답이 아니다 — 정보성 비교일 뿐 돈을 옮기지 않는다. 관련 위험은 `01_prd.md` §21.3에 남겨 둔다.

## 3. 문서 사용 규칙

1. 발표·PRD·디자인 리뷰에서 `핵심 유저 플로우`와 `CUJ`를 같은 뜻으로 쓰지 않는다.
2. 화면 순서나 분기가 바뀌면 IA를 먼저 갱신하고, 핵심 가치의 시작·완결이 바뀔 때만 이 문서를 갱신한다.
3. 감정·이탈 이유는 실사용 검증 전까지 가설로 표시한다. 관찰되지 않은 감정을 고객 사실로 바꾸지 않는다.
4. 기능 우선순위 판단 시 “이 기능이 없으면 §2의 가치 완결이 불가능한가?”를 Must 판단 기준으로 사용한다.
5. CUJ 완료를 온보딩 완료로 대체하지 않는다. 활성화 이후 실제 거래 반영과 월말 결과 확인까지 추적한다.
6. 알림·발화 관련 판단은 `04_스펙/01_prd.md`가 아니라 `04_스펙/06_지킴이_Agent_설계.md` §3 개입 케이스를 먼저 본다.
