## 폴더 구조

```text
00_서비스개요.md   ← 메인. 제품 개요
01_고객/           누구의 무슨 문제인가
02_시장/           시장 크기·경쟁·사업성
03_솔루션/         어떻게 푸는가
04_스펙/           무엇을 만드는가 (PRD·Agent 계약·IA)
_history/          왜 두 번 피봇했는가 (과정 기록 · 정본 아님)
_legacy/           폐기된 세대0·세대1 (참고 보존)
```

- **현재 정본** = `00_서비스개요` + `01~04/` (세대2 · MOA).
- **`_history/`** = 과정 기록. 정본 스펙은 아니지만 발표·포트폴리오의 핵심 서사.
- **`_legacy/`** = 세대0(완전초기)·세대1(1차). 폐기된 방향.

> **파일 번호 규칙**: 번호는 **폴더 안에서만** 매긴다 — 각 폴더가 `01`부터 새로 시작한다.
> 그래서 폴더가 다르면 번호가 겹친다(`02_시장/01`과 `04_스펙/01`은 다른 문서다).
> 문서를 부를 땐 번호만 쓰지 말고 **파일명 전체**(`04_스펙/01_prd.md`)로 쓴다.
> `04_스펙`의 Agent 설계 3종은 **①②③ 순서**(05=①소비분석 · 06=②지킴이 · 07=③취향·추천)로 번호가 붙어 있다.
