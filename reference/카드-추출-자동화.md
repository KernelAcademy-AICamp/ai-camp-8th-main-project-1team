## 0. 한 줄로

**로컬 PDF 원문을 LLM 에 통째로 넣어 카드 한 장을 JSON 한 개로 뽑는 파이프라인**을 만든다.
지금 카탈로그는 사람이 손으로 대조한 **3장**뿐이고, 이걸 **29장**으로 늘리는 것이 이번 일이다.

### 끝났다고 말할 수 있는 조건

```text
1  BC active 의 텍스트 추출 가능한 29장이 전부 JSON 으로 나온다
2  build_catalog.py 가 그 29장을 sys.exit(1) 없이 통과한다

4  ./mvnw test 가 그대로 통과한다 (카드 시험 11개 포함)
```

**3번이 이 작업의 목적이다.** 통과율이 높으면 나머지 16,253건을 마저 받을 이유가 생기고,
낮으면 범위를 좁혀야 한다. 지금은 표본이 3장이라 아무도 모른다.

## 2. 원문은 어디 있나

**저장소 밖이다 — 이유는 용량 하나뿐이다.**

```text
PDF 142장 = 313MB   (평균 2.2MB · 중앙값 1.0MB · 최대 45.3MB)
저장소 .git 전체     126MB
```

원문만 넣어도 저장소가 **2.5배**가 되고, 그것도 BC·신한 둘만 받은 상태다. 목록에 남은
16,253건까지 받으면 산술적으로 30GB 대다. git 은 바이너리를 델타 압축하지 못해 한 번
들어가면 이력에서 못 뺀다.

> **민감정보라서가 아니다.** 이 PDF 들은 카드사가 내는 **상품설명서**, 즉 법정 공시 문서다.
> 누구나 받을 수 있는 공개 자료라 마스킹·비식별 처리를 할 것이 없다. 폴더 이름의 '개인카드'는
> **법인카드와 구분되는 상품 종류**를 말한다. 실제 개인정보(사람의 명세서)는 다른 곳
> (`_archive/`)에 있고 이 작업과 무관하다. **평범하게 읽고 쓰면 된다.**

```text
/Users/monicalee/Desktop/dev/ssangtokle/개인카드-로컬전용/
  bccard_terms/active/     PDF 54개   ← 이번 대상
  bccard_terms/stopped/    PDF 57개   ← 발급중단. 이번엔 안 건드린다
  shinhancard_terms/       PDF 24개   ← 다음 차례
  (현대·국민·롯데·농협·삼성·우리 = 목록만, PDF 7개)
```

**실측(2026-08-12)** — `bccard_terms/active` 54장 중

```text
텍스트 추출 가능   29장   ← 이번 대상
스캔 이미지        25장   ← 건너뛴다(게이트 1 이 거른다). OCR 하지 마라
```

판별 기준은 **쪽당 200자**다. `pdftotext -layout` 로 뽑아 공백 뺀 글자 수를
`pdfinfo` 의 쪽수로 나눠 200 미만이면 스캔으로 본다. 위 29/25 가 이 기준으로 센 값이다.

> 스캔본이 옛날 카드가 아니다 — 2022년이 최다다. 카드사가 상품설명서를 디자이너가
> 카드마다 따로 그린 리플렛으로 내기 때문이다(Illustrator·InDesign). **스캔인 카드는
> OCR 대신 HTML 공시로 메우는 편이 싸다.** 그건 이번 범위가 아니다.

## 3. 만들 것 — `scripts/collect-cards/extract_llm.py`

```text
python3 scripts/collect-cards/extract_llm.py \
    --src ~/Desktop/dev/ssangtokle/개인카드-로컬전용/bccard_terms/active \
    --out scripts/collect-cards/cards/
```

한 카드 = 한 PDF = **JSON 파일 하나**. 파일명은 `BC카드-104520.json` 처럼
`{issuer}-{product_id}.json`.

### ★ 전문을 넣는다. 발췌하지 마라

**이것이 이 작업에서 가장 중요한 규칙이다.**

상품설명서는 **3단 편집**이라, `grep` 이나 정규식으로 첫 매치 주변을 잘라 읽으면
**같은 줄에 있는 다른 칼럼 조각이 섞여 들어온다.** 실제로 이것 때문에 KaPick 의
실적 제외를 **12개짜리를 1개로** 읽은 적이 있다(지면에 박스가 둘인데 위쪽만 읽었다).

```python
text = subprocess.run(["pdftotext", "-layout", pdf, "-"], ...).stdout
# 이 text 를 통째로 프롬프트에 넣는다. 크기는 아래 실측대로 감당된다.
```

**크기 실측(2026-08-12, 텍스트 나오는 29장)** — 중앙값 **7,881자** · 평균 12,088자 ·
최대 29,377자. 한 장을 통째로 넣어도 컨텍스트가 남는다. **자를 이유가 없다.**

`scripts/collect-cards/extract_pdf.py` 는 **정규식 파서다. 참고만 하고 따라가지 마라** —
바로 그 방식이 위 사고를 냈다. 이번 것은 별도 파일로 만들고 기존 것은 그대로 둔다.

### 모델

프로젝트는 Gemini 를 쓴다. 설정은 `application.yml` 의 `finntech.gemini` 절이고
키는 환경변수 `GEMINI_API_KEY` 다.

- **키 값을 출력·로그·커밋에 남기지 마라.** 확인이 필요하면 설정 여부와 길이만 찍는다.
- 모델 이름을 코드에 박지 말고 `GEMINI_MODEL` 로 받되, 기본값은 `gemini-3.1-flash-lite`.
  `-latest` 계열은 어느 등급에 붙을지 우리가 못 정한다(비용이 튄다).
- 추출은 **JSON 만** 답하게 한다. 설명 문장을 섞으면 파싱이 깨진다.

## 4. 출력 계약 — 이 모양이어야 `build_catalog.py` 가 먹는다

정본 예시는 **`scripts/collect-cards/schema-draft.json` 의 3장**이다. 그 파일을 열어
BC 바로 ZONE·페이북·KaPick 이 어떻게 생겼는지 보고 **같은 모양으로 맞춰라.** 셋이 서로
충분히 달라서(할인/적립 · 2구간/4구간 · 통합한도 유/무 · 원/포인트/제3자포인트)
스키마가 흔들릴 축은 이미 다 나와 있다.

핵심만 옮기면:

```jsonc
{
  "issuer": "BC카드",
  "name": "BC 바로 ZONE",
  "product_id": "104520",          // 카드사 내부 상품번호. 재적재의 키다
  "status": "active",
  "as_of": "2025-11-07",           // ★ 여신금융협회 심의필 날짜. 없으면 참고 모드로 떨어진다
  "review_no": "여신금융협회 심의필 제2025-C1a-16209호",
  "posted_at": "2025-11-27",
  "annual_fee": [
    { "scope": "국내전용", "brand": "BC", "total": 19000, "base": 10000, "affiliate": 9000 }
  ],
  "performance": {
    "period": "전월 1일~말일",
    "basis": "승인일",
    "basis_exceptions": { "basis": "매입일", "applies_to": ["해외결제", "무승인결제(...)"] },
    "tiers": [300000, 600000],     // ★ 개수가 카드마다 다르다. 2~4단
    "excluded": [ { "code": "TRANSIT", "label": "대중교통(시내버스·지하철), ..." } ]
  },
  "benefits": [
    {
      "group": "EAT-ZONE",
      "kind": "할인",              // 할인 | 적립 | 무이자할부
      "rate_percent": 7,
      "requires_tier": 300000,     // ★ tiers 에 있는 값이어야 한다
      "targets": [
        { "category": "커피",
          "brands": ["스타벅스", "투썸플레이스"],
          "channel": ["오프라인 현장결제", "브랜드 공식앱"],
          "exclude_place": ["백화점", "면세점", "공항"] },
        { "category": "교통", "industries": ["시내버스", "지하철"] }
      ],
      "monthly_cap_by_tier": { "300000": 5000, "600000": 10000 }  // ★ 키가 tiers 와 같아야
    }
  ],
  "combined_caps": [               // 통합한도가 있을 때만
    { "group": "특별적립", "members": ["종합몰","패션몰"], "cap_by_tier": { "400000": 13000 } }
  ],
  "benefit_excluded": [ { "code": "INSTALLMENT_FREE", "label": "무이자 할부 이용금액" } ],
  "non_monetary": ["해외겸용 시 Mastercard Platinum 등급 기본 서비스"]
}
```

### 놓치면 반드시 틀리는 것 넷

1. **혜택 제외 ≠ 실적 제외.** 목록이 둘이고 서로 다르다. `performance.excluded` 와
   `benefit_excluded` 를 각각 채워라. ZONE 은 무이자할부를 혜택에서만 빼고 실적에는 넣는데,
   KaPick 은 둘 다 뺀다. **지면에 박스가 둘일 수 있다** — 하나만 읽고 끝내지 마라.
2. **실적 제외 목록은 카드마다 다르다.** ZONE 은 대중교통을 빼는데 KaPick 은 안 뺀다.
   공통 목록으로 뭉치면 실적이 통째로 틀린다.
3. **`tiers` 는 고정 배열이 아니다.** ZONE 2단, 페이북 2단, KaPick 4단.
   `monthly_cap_by_tier` 의 키가 `tiers` 에 없으면 DB 가 거부한다(그전에 게이트가 잡는다).
4. **표의 병합셀.** KaPick 생픽은 `{15만:3000, 30만:3000, 60만:6000, 100만:6000}` 인데,
   지면에는 3천이 두 구간에 걸친 병합셀로 그려져 있다. 텍스트만 보면 개수가 안 맞는다.

### 어휘 — 여기 없는 말을 쓰면 빌드가 선다

`build_catalog.py` 는 **모르는 말이 나오면 `sys.exit(1)` 로 멈춘다.** 조용히 넘기면 그 혜택이
계산에서 사라진 것을 아무도 눈치채지 못하기 때문이다. 새 말이 나오면 **사람이 검토해서**
아래 표에 더한다(`INDUSTRY_TO_AXIS`, `EXCLUSION_CODE_TO_AXES`).

**`targets[].industries` 에 쓸 수 있는 업종 표현** — 지금 표에 셋뿐이다.

```text
시내버스 · 지하철 → 대중교통
SKT/KT/LGU+ 휴대폰요금 자동이체 → 통신
```

**실적/혜택 제외 코드** — 지금 14개.

```text
TRANSIT · PUBLIC_DUES · UTILITY · SOCIAL_INS · TAX · PENALTY · HOUSING · TUITION
CASH_ADVANCE · CARD_LOAN · FEE · GIFT_CARD · INSTALLMENT_FREE · PUBLIC_MERCHANT
```

**카드혜택 축 21종**(참고 — 카드 JSON 에 직접 쓰지 않고 `build_catalog.py` 가 배정한다):
주유 · 온라인쇼핑 · 통신 · 여행/항공 · 대중교통 · 카페/디저트 · 공과금/렌탈 · 쇼핑 ·
편의점 · 마트 · 외식 · 병원/약국 · 디지털구독 · 영화/문화 · 뷰티 · 택시 · 백화점/면세점 ·
교육/육아 · 스포츠/레저 · 애완 · 혜택축없음

## 5. `build_catalog.py` 에 해야 할 수정

지금은 `schema-draft.json` **한 파일만** 읽는다. `cards/` 디렉터리도 읽게 고쳐라.

```python
DRAFT = .../schema-draft.json      # 사람이 원문 대조한 3장 — 그대로 둔다
CARDS = .../cards/                 # LLM 이 뽑은 것 — 새로 읽는다
```

**두 출처를 섞되 구분은 남겨라.** 카드마다 `extraction` 을 `HUMAN_VERIFIED` / `LLM` 로
적고 카탈로그까지 들고 가라. 나중에 "이 값을 사람이 봤나"를 물을 자리가 반드시 온다.

`product_id` 가 겹치면 **사람이 대조한 쪽이 이긴다.**

### 무엇을 커밋하나 — 여기 틀리면 배포에서 카드가 통째로 사라진다

| | |
|---|---|
| `scripts/collect-cards/cards/*.json` | **커밋한다.** 산출물이 아니라 원천이다(`schema-draft.json` 과 같은 급). 사람이 나중에 들여다볼 기록이기도 하다 |
| `backend/src/main/resources/card-catalog.json` | **반드시 커밋한다.** 앱이 **기동할 때 이 파일을 읽어** 표를 채운다. 빠지면 어느 환경에서도 카드가 0장이고, **기동은 성공하므로 아무도 모른다** |
| `scripts/collect-cards/out/` | 안 한다(이미 `.gitignore`) |
| PDF 원문 | 안 한다. 저장소 밖이 정본이다 |

둘 다 지금 `.gitignore` 에 안 걸려 있다. **새로 추가하지 마라.**

## 6. 검산 — 게이트 3 은 이미 있다

`build_catalog.py` 가 카드마다 여섯을 본다. 하나라도 걸리면 `grade = REFERENCE` 가 되고
**화면에 숫자를 안 보여준다.** 빌드를 실패시키진 않는다(카드 한 장 때문에 전체가 막히면 안 된다).

```text
실적 제외 항목 수 < 5           → 참고   ← KaPick 사고를 잡았을 규칙
총연회비 != 기본 + 제휴          → 참고
실적 구간이 오르는데 한도가 내려감  → 참고
한도의 구간 키가 tiers 에 없음    → 참고
셈할 수 있는 혜택이 하나도 없음    → 참고
as_of 없음                     → 참고
```

### ⚠ 게이트 3 이 못 잡는 것 — 여기에 대한 판단이 필요하다

게이트 3 은 **구조 이상**을 잡지 **값이 틀린 것**은 못 잡는다. LLM 이 `7%` 를 `5%` 로 읽으면
여섯 개 전부 통과한다. 지금 설계는 "게이트 3 통과 = PRECISE" 인데, 사람이 한 번도 안 본
29장에 그대로 적용하면 **틀린 숫자가 정밀로 보인다.**

값싼 방어 둘을 **제안한다**(채택 여부는 사람이 정한다 — 그대로 밀지 말고 물어라):

- **두 번 뽑아 대조.** 같은 PDF 를 온도만 바꿔 두 번 넣고 결과를 비교해, 어긋나면
  `REFERENCE`. 요율·한도·구간 같은 숫자 칸만 봐도 충분하다. 비용은 2배지만 원문이 중앙값
  7,881자라 29장을 두 번 돌려도 얼마 안 된다.
- **월 최대 혜택 대조.** `max(구간별 한도 합)` 을 계산해 카드 비교 서비스가 표시하는 값과
  맞춰 본다. 우리 파싱이 맞았는지 **바깥 기준으로 채점**되는 유일한 지점이다.
  화면 정렬에는 쓰지 않는다(100% 활용 전제라 개인화 추천과 안 맞는다).

## 8. 다 하면 돌릴 것

```bash
# 1. 카탈로그 재생성 — 여기서 통과율이 찍힌다
python3 scripts/collect-cards/build_catalog.py

# 2. 시험 (카드 시험 11개 포함 전체)
cd backend && ./mvnw test
```

`build_catalog.py` 의 마지막 줄이 이렇게 나온다:

```text
카드 29장 (정밀 N · 참고 M) · 혜택 N개(셈 가능 N) · 대상 N행
```

### 보고할 것

1. **통과율** — 29장 중 PRECISE 몇 장인가
2. **참고로 떨어진 카드가 왜 떨어졌나** — `gradeReason` 을 모아 유형별로
3. **어휘 표에 몇 개를 더했나** — `INDUSTRY_TO_AXIS`·`EXCLUSION_CODE_TO_AXES`
4. **스키마로 못 담은 것** — "생일월 한도 2배", "영화관 연 4회", "실적유예", "실적 채워드림"
   같은 것이 나올 것이다. **버리지 말고 목록으로 남겨라** — 칸을 더할지는 사람이 정한다

이 넷이 "16,253건을 마저 받을지"의 판단 재료다. 통과율만 갖고 오면 결정을 못 한다.
