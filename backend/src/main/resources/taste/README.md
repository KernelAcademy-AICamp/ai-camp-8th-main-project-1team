# taste/hobbies.json — 취향 분석용 취미 매핑

**출처**: `backend-mydata/src/main/resources/generation/catalog/hobbies.json`의 복사본.

마이데이터 생성기(backend-mydata)가 사용자에게 취미를 배정할 때 쓰는 `취미유형 → signatureCategories`
매핑이다. 분석 서버(backend)는 모듈이 분리돼 그 리소스를 직접 못 읽으므로 여기에 복사해 둔다.
`TasteAnalysisService`가 이 매핑을 **역방향**(category2 → 취미유형)으로 뒤집어 소비내역에서 취향을 읽는다.

원본이 바뀌면 이 파일도 갱신한다(생성기와 분석기가 같은 택소노미를 봐야 정답 라벨로 채점 가능).
카테고리를 코드에 박지 않는다는 설계원칙 4에 따라 코드가 아닌 데이터(리소스)로 둔다.

## 생성기 원본과의 의도적 차이 (③ 분석용 확장)

생성기 `category2`는 취향을 뭉뚱그리는 지점이 있어 그대로 매핑하면 취향이 왜곡된다. 대표적으로
**`스트리밍`은 음악(멜론)·영상(넷플릭스)·독서(밀리의서재)·AI(챗지피티)가 한 카테고리에 섞여** 있다.
원본에선 `스트리밍`이 `디지털게임`·`영화관람`의 signature라 멜론(음악)이 게임·영화로 새어 나갔다.

그래서 이 파일은 원본에서 **다음을 확장**한다(생성기 `contexts.json`은 건드리지 않는다 — 파급이 크고 비현실적):

1. `refineByMerchant` 블록 신설 — `category2 → (세분유형 → 가맹점명 키워드)`. 분석 시 가맹점명 **부분일치**로
   `스트리밍`을 `음악감상`/`영상시청`/`독서구독`으로 가른다. "멜론"이든 "멜론 스트리밍"이든 substring으로
   잡혀 seed 어휘(`Catalog.MERCHANTS`: 넷플릭스/유튜브프리미엄/멜론)와 generation 어휘(products.json: 멜론
   스트리밍/스포티파이…)를 **둘 다** 커버한다. 매칭이 없으면 원 category2 유지 → 챗지피티(AI)는 취미 아님.
2. 취미 `음악감상` 신설(세분유형 `음악감상`), `영화관람`에 `영상시청` 추가, `독서문화`에 `독서구독` 추가.
3. `디지털게임`·`영화관람`에서 원래의 `스트리밍` signature 제거(멜론 오분류 차단).

세분·매핑은 모두 이 리소스(데이터)에 있고 코드에 카테고리를 박지 않는다(설계원칙 4). 로직은
`HobbyCatalog`(로드)와 `TasteAnalysisService.refineCategory2`(부분일치)에 있다.
